클로드 코드 설치는 명령어 한 줄이면 된다.

맥을 쓴다면 터미널에 한 줄 붙여 넣고 엔터만 치면 끝이다. 나도 깔면서 막힌 적은 한 번도 없었다. 지금 내 맥에 깔린 버전은 2.1.319다.

다만 설치만 끝내고 바로 쓰면 아쉬운 점이 두 가지 남는다. 클로드는 내 프로젝트를 전혀 모르는 상태로 시작하고, 작업을 할 때마다 일일이 내 허락을 구할 수 있다. 그래서 나는 설치 직후에 늘 두 가지를 먼저 해 둔다. CLAUDE.md를 만들고, 권한 확인을 건너뛰는 모드를 켜는 것이다.

두 번째 설정에는 위험이 따른다. 그 위험까지 이 글에서 함께 짚어 본다.

(2026년 11월 기준. 설치 명령과 메뉴는 버전에 따라 바뀔 수 있으니 공식 문서 code.claude.com/docs 를 한 번 더 확인하자.)

## 설치 전에 무엇이 필요할까?

딱 세 가지면 된다.

- **유료 계정.** 무료 플랜에서는 클로드 코드를 쓸 수 없다. Pro, Max, Ultra 같은 유료 플랜이나 API용 Console 계정이 필요하다. 어떤 플랜으로 시작할지는 [요금제 글](https://kmsk99.github.io/post/claude-code-plans/)에 정리해 두었다.
- **컴퓨터.** macOS 13 이상, 윈도우 10(1809) 이상, 우분투 20.04 이상 같은 환경을 지원하며, 메모리는 4GB 이상이면 충분하다.
- **인터넷.** 설치할 때는 물론이고, 쓰는 동안에도 연결돼 있어야 한다.

터미널이 낯설다면 데스크톱 앱으로 쓰는 길도 있다. 하지만 이 글은 터미널을 기준으로 설명한다.

## 클로드 코드는 어떻게 설치할까?

공식 문서가 권하는 건 '네이티브 설치'다. 당신의 운영체제에 맞는 명령어 한 줄을 터미널에 붙여 넣으면 된다.

맥, 리눅스, 윈도우의 WSL:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

윈도우 PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

윈도우 CMD:

```batch
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

윈도우에서 지금 열린 창이 PowerShell인지 CMD인지 헷갈리면 줄 맨 앞을 보자. `PS C:\`로 시작하면 PowerShell이고, `PS` 없이 `C:\`로 시작하면 CMD다. 공식 문서는 윈도우 환경에서 Git for Windows를 함께 깔아 두길 권한다. 이게 없으면 클로드가 명령을 PowerShell로 실행한다.

설치가 돌아가는 동안 화면에는 별다른 진행 표시가 뜨지 않는다. 멈춘 것처럼 보여도 그냥 기다리면 된다.

이렇게 설치하면 알아서 업데이트된다는 게 가장 큰 장점이다. Homebrew(`brew install --cask claude-code`)나 WinGet(`winget install Anthropic.ClaudeCode`)으로도 깔 수 있지만, 그쪽은 업데이트를 직접 챙겨야 한다.

설치가 끝났다면 **터미널을 새로 열고** 버전을 확인해 보자.

```bash
claude --version
```

화면에 `2.1.319 (Claude Code)`처럼 버전 숫자가 찍히면 성공이다. 만약 `claude`를 찾을 수 없다고 나오면, 설치는 됐는데 터미널이 아직 파일 위치를 못 찾는 상태다. 공식 문서의 설치 문제 해결 페이지에 가 보면 고치는 방법이 나와 있다.

## 로그인은 어떻게 할까?

작업할 프로젝트 폴더로 이동해서 `claude`를 실행한다.

```bash
cd 내-프로젝트-폴더
claude
```

처음 실행하면 웹 브라우저가 자동으로 열린다. 거기서 클로드 계정으로 로그인만 마치면, 다시 터미널로 돌아와 바로 대화를 시작할 수 있다.

![클로드 코드 설치는 세 단계다. 한 줄 붙여 넣기, 버전 확인, 프로젝트 폴더에서 실행하고 브라우저로 로그인](/images/claude-code-install/fig-install-steps.png)

설치는 이게 전부다. 전혀 어렵지 않지만, 진짜 신경 써야 할 건 그다음부터다.

## 왜 CLAUDE.md부터 만들까?

클로드 코드는 새 세션을 열 때마다 머릿속이 하얗게 비어 있다. 어제 나눈 이야기를 오늘 기억하지 못한다.

일 잘하는 아르바이트생이 새로 왔다고 치자. 손은 빠른데 매일 아침 첫 출근인 것처럼 나타난다. \"포장은 이렇게 하고, 저 선반은 건드리지 마\" 같은 말을 매일 아침 되풀이해야 한다면 얼마나 피곤할까. 벽에 메모 한 장만 붙여 두면 매번 입 아플 일이 사라진다.

클로드 코드에서는 CLAUDE.md가 바로 그 메모지다. 세션을 시작할 때마다 클로드가 가장 먼저 읽는 파일이며, 두는 위치는 두 곳이다.

- **`~/.claude/CLAUDE.md`** — 내 컴퓨터의 모든 프로젝트에 공통으로 들어간다. \"답은 한국어로\"처럼 내 작업 습관을 적어 둔다.
- **프로젝트 폴더의 `CLAUDE.md`** — 해당 프로젝트에만 적용된다. 빌드 명령이나 폴더 구조, 꼭 지켜야 할 규칙을 적는다.

백지에서 직접 다 쓸 필요도 없다. 클로드 코드 창에서 `/init`을 치면 클로드가 프로젝트 구석구석을 훑어보고 첫 CLAUDE.md를 알아서 짜 준다. 이미 파일이 있다면 덮어쓰는 대신 고칠 점을 제안해 준다.

![CLAUDE.md 예시. 가상의 예약 앱 프로젝트에 맞춰 만든 짧은 예다](/images/claude-code-install/fig-claude-md.png)

## CLAUDE.md에는 무엇을 적을까?

공식 문서가 알려 주는 요령은 명확하다. 구체적으로 적으라는 것이다. \"코드를 깔끔하게\" 같은 모호한 말보다 \"커밋 전에 `npm test`를 돌린다\"처럼 클로드가 그대로 행동에 옮길 수 있는 문장이 훨씬 낫다.

권장하는 길이도 있다. 파일 하나당 200줄을 넘기지 않는 게 좋다. 글이 길어질수록 매번 읽어야 할 양이 늘어나고, 정작 중요한 지시를 흘려들을 수 있다고 한다.

내가 실제로 쓰는 설정을 털어놓자면 이렇다.

- **전역 `~/.claude/CLAUDE.md`는 26줄이다.** 모든 프로젝트에서 기억 도구를 어떻게 다룰지, 다른 AI에게 일을 넘길 때 무엇을 지킬지 적어 두었다.
- **내 지식 저장소의 `CLAUDE.md`는 딱 한 줄이다.** `@AGENTS.md`. 진짜 지침은 AGENTS.md에 다 들어 있고, 클로드는 이 한 줄을 보고 그 파일을 끌어와 읽는다.

굳이 한 줄만 적어 둔 이유가 있다. 이 저장소는 클로드 코드 말고도 코덱스 같은 다른 AI 도구들이 함께 건드리는 곳인데, 그 도구들은 AGENTS.md를 읽는다. 지침을 한곳에 몰아 두어야 이쪽만 고치고 저쪽은 깜빡하는 실수를 막을 수 있다. 이 구조에 대해서는 [코덱스 CLI 글](https://kmsk99.github.io/post/codex-cli/)에 더 자세히 적어 두었다.

여기서 한 가지 고백할 게 있다. 내 AGENTS.md는 무려 371줄이다. 공식 권장 분량의 두 배에 가깝다. `@`로 불러온 파일도 어차피 함께 읽히니 길이에 따른 부담은 똑같다. 당신이 처음 만든다면 가볍게 200줄 안에서 시작하길 권한다.

클로드에게 똑같은 설명을 세 번 넘게 반복하고 있다면, 바로 그 문장을 CLAUDE.md의 첫 줄에 적으면 된다.

## 권한 확인 건너뛰기는 무엇을 바꿀까?

클로드 코드에는 '권한 모드'라는 스위치가 있다. 파일을 고치거나 터미널 명령을 돌리기 전에 나에게 일일이 물어볼지 정하는 기능이다.

공식 문서 기준으로 주로 쓰이는 모드는 네 가지다.

- **수동(default).** 읽는 것만 혼자 하고, 무언가 고치거나 실행할 때마다 허락을 구한다.
- **편집 허용(acceptEdits).** 파일 수정이나 폴더 생성처럼 흔한 작업은 묻지 않고 넘어간다.
- **자동(auto).** 알아서 작업을 진행하되, 뒤에서 다른 AI가 위험한 행동을 걸러 낸다.
- **권한 건너뛰기(bypassPermissions).** 아무것도 묻지 않고 전부 실행한다.

내가 켜 두고 쓰는 건 마지막 모드다. 흔히 인터넷에서 'dangerously skip permissions'라고 부르는 옵션이 바로 이것이며, 아래 두 명령 중 하나로 켤 수 있다.

```bash
claude --dangerously-skip-permissions
claude --permission-mode bypassPermissions
```

둘 다 똑같이 동작한다. 처음 실행하면 경고 창이 뜨는데, 여기서 동의하면 설정 파일(`~/.claude/settings.json`)에 다음부터 경고를 띄우지 말라는 기록이 남는다. 내 설정 파일에도 그 표시가 박혀 있다.

![클로드 코드 권한 모드 비교. 오른쪽으로 갈수록 덜 묻고, 그만큼 내가 확인하는 기회가 줄어든다](/images/claude-code-install/fig-permission-modes.png)

## 그런데 왜 위험한 이름이 붙었을까?

옵션 이름에 굳이 'dangerously'가 붙은 데는 다 이유가 있다. 공식 문서의 설명을 그대로 가져오면 이렇다.

- 확인 창과 안전 검사를 전부 끄고, 클로드의 행동을 즉시 실행한다.
- `.git`이나 `.claude` 같은 보호된 폴더에도 묻지 않고 파일을 쓴다.
- 프롬프트 인젝션에 무방비다. 클로드가 읽은 웹페이지나 파일 안에 악의적인 지시가 숨어 있으면, 그 지시대로 움직일 위험이 있다.
- 그래서 **인터넷이 끊긴 컨테이너나 가상 머신처럼, 클로드가 내 컴퓨터를 망가뜨릴 수 없는 격리된 환경에서만** 쓰라고 못 박아 두었다.

그렇다고 정말 모든 고삐가 풀리는 건 아니다. 내가 미리 '이건 금지'라고 지정해 둔 거부 규칙은 이 모드에서도 여전히 작동한다. 컴퓨터 최상위 폴더나 홈 폴더, 작업 폴더를 통째로 날리려는 명령을 치면 터미널이 한 번 더 확인을 요구하고, 관리자 권한(root, sudo)으로는 아예 이 모드를 켤 수 없다.

솔직히 말하면, 나는 공식 문서가 말하는 격리된 환경이 아니라 매일 쓰는 맥에서 그냥 이 모드를 켜 둔다. 여러 세션을 띄워 관리하는 Paseo라는 도구의 에이전트 프로필도 이 모드로 맞춰 놓았다. 공식 권장 사항을 어기며 쓰고 있는 셈이다.

그래도 나는 켜 두는 쪽이 훨씬 편하다. 하루에도 클로드 코드 세션을 여러 개씩 동시에 돌려 놓는데, 세션 하나가 내 허락을 기다리며 멈춰 버리면 내가 그 창을 다시 볼 때까지 작업이 올스톱되기 때문이다. 대신 절대 깨지면 안 되는 규칙은 다른 안전장치로 막아 둔다. 예컨대 내 지식 저장소에서는 원자료 폴더를 수정하거나 지우면 git 커밋 단계에서 자동으로 걸러진다. 클로드의 권한 모드와 무관하게 밖에서 돌아가는 검사다.

## 누구에게나 맞는 설정일까?

그렇지 않다. CLAUDE.md는 누구에게나 추천하지만, 권한 건너뛰기는 사정이 다르다.

마침 공식 기본값도 바뀌었다. 2.1.283 버전부터는 터미널에서 클로드 코드를 켜면 처음부터 자동(auto) 모드로 들어간다. 성가신 확인 창은 확 줄이면서도, 뒤에서 다른 AI가 위험한 행동을 알아서 막아 주는 모드다. 인터넷에서 받은 코드를 곧바로 실행하려 하거나, 세션 시작 전부터 있던 파일을 복구 불가능하게 지우는 행동은 기본적으로 차단된다. 공식 문서에서도 확인 창이 귀찮다면 권한 건너뛰기 대신 자동 모드를 쓰라고 권한다. 클로드 코드를 막 설치한 당신이라면 이 기본값만으로도 충분할 것이다.

특히 아래에 해당한다면 권한 건너뛰기는 켜지 않는 편이 낫다.

- 회사 컴퓨터이거나, 회사 코드와 고객 정보가 담긴 폴더에서 일할 때
- 클로드에게 처음 보는 웹페이지나 남이 보낸 파일을 읽힐 때
- 백업이 전혀 없고, git으로 되돌릴 수도 없는 폴더를 다룰 때
- 클로드가 어떻게 움직이는지 아직 감이 안 잡히는 첫 주

굳이 켜고 싶다면 순서를 지키자. 며칠 동안은 클로드가 어떤 명령을 치는지 눈으로 지켜보고, git처럼 언제든 되돌릴 수 있는 안전망을 갖춘 뒤에 켜도 늦지 않다.

방금 클로드 코드를 깔았다면, 일단 프로젝트 폴더에서 `claude`를 열고 `/init`부터 입력해 보자.
