나는 터미널에서 코덱스 CLI를 직접 여는 날이 거의 없다. 그런데도 코덱스는 매일 돌아간다. 내가 아니라 클로드 코드가 일을 시키기 때문이다.

지금 읽는 이 글의 설치 방법과 설정도 코덱스 일꾼이 공식 문서를 뒤져 찾아 왔다. 지시는 클로드 코드가 내렸고, 나는 다 끝난 결과만 받아 봤다.

물론 처음부터 이렇게 썼던 건 아니다.

(2026년 11월 기준, 내 환경은 codex-cli 0.166.0이다.)

## 코덱스 CLI가 뭘까?

OpenAI에서 만든 터미널용 코딩 에이전트다. 클로드 코드처럼 터미널 창에서 대화를 주고받으며 코드를 읽고 고친다.

설치는 아래 두 줄 가운데 편한 걸로 하면 된다.

```
npm install -g @openai/codex
brew install --cask codex
```

로그인은 ChatGPT 계정이나 API 키 둘 다 지원한다. 계정으로 로그인하면 요금제 한도 안에서 차감되고, API 키를 넣으면 쓴 만큼 비용이 나간다. macOS와 리눅스, 윈도우에서 모두 돌아가며 윈도우에서는 WSL2 환경도 쓸 수 있다.

![codex --version과 codex --help 출력. codex-cli 0.166.0, exec·login·resume 명령](/images/codex-cli/term-install.png)

*설치하면 codex 명령이 생긴다. exec는 대화 없이 일을 시킬 때, resume은 끊긴 세션을 이어 갈 때 쓴다*

## 처음엔 어떻게 쓰게 됐을까?

원래 나는 클로드보다 ChatGPT를 먼저 썼다. 웹에서 채팅으로만 쓰다가 코덱스가 나왔다는 소식에 자연스럽게 넘어갔다.

본격적으로 손에 익힌 건 카카오톡 프로모션 덕분이었다. ChatGPT 프로를 플러스 요금으로 5개월 동안 쓸 수 있었는데, 그때 써 보니 클로드 코드에는 살짝 못 미쳐도 꽤 쓸 만했다.

지금은 월 200달러짜리 ChatGPT Pro를 구독 중이다. 굳이 클로드와 함께 쓰는 이유는 [지난 글](https://kmsk99.github.io/post/claude-code-plans/)에 자세히 적어 뒀는데, 이미지를 바로 뽑아낼 수 있고 사용량 한도가 넉넉해서다.

## 왜 직접 안 쓰고 클로드 코드에게 시킬까?

혼자 코덱스를 돌릴 때 제일 답답했던 건 세션이 소리 소문 없이 죽는 문제였다.

할 일을 던져 두고 한참 뒤에 돌아와 보면 아무런 예고도 없이 멈춰 있곤 했다. 작업 도중 용량 부족(capacity) 오류가 뜨면 그냥 그 자리에서 종료돼 버리는 식이라, 매번 내가 직접 확인하고 다시 이어 붙여야 했다.

이 귀찮은 일을 클로드 코드에게 맡기면서 문제가 풀렸다. 코덱스 세션이 중간에 끊기더라도 클로드 코드가 알아서 상태를 확인하고 같은 세션을 다시 살려낸다. 내가 화면 앞을 지킬 이유가 사라진 셈이다.

덕분에 요즘 내가 직접 터미널에 코덱스를 띄우는 건 컴퓨터 화면이나 브라우저 창을 건드려야 할 때뿐이다. 나머지 작업은 대개 클로드 코드 손을 거친다.

혹시 당신도 코덱스에 긴 작업을 맡겨 뒀다가 멈춰 버린 화면을 뒤늦게 발견한 적이 있다면, 감시역부터 다른 에이전트에게 넘겨 보길 권한다.

## 클로드 코드는 코덱스에게 어떻게 일을 시킬까?

이 과정을 자동화하려고 `agent-delegate`라는 스킬을 직접 만들어 붙였다. 클로드 코드가 이 스킬 파일을 읽은 뒤 정해진 절차에 따라 코덱스 일꾼을 부린다.

흐름은 단순하다.

- **일을 적는다.** 클로드 코드가 목표와 작업 폴더, 허용 범위와 금지 사항(커밋 금지, 결제 금지 등), 결과물 저장 위치를 지시서 한 장에 정리한다.
- **일꾼을 띄운다.** 작업에 맞춰 모델과 추론 강도(effort)를 고른 뒤 코덱스를 실행한다. 일꾼마다 터미널 창이 따로 열려 어떻게 돌아가는지 눈으로 볼 수 있다.
- **기다린다.** 모든 일꾼을 한꺼번에 묶어 기다리지 않는다. 먼저 끝난 쪽부터 결과를 챙기고, 그사이에 다른 일꾼들은 자기 일을 계속한다.
- **확인한다.** 일꾼이 \"다 했다\"고 보고해도 곧이곧대로 믿지 않는다. 클로드 코드가 결과 파일을 직접 열어서 시킨 범위를 벗어나지 않았는지 대조한다.
- **이어서 시킨다.** 추가로 시킬 작업이 남았거나 도중에 세션이 죽었으면 같은 세션 번호를 물려 다시 돌린다. 작업이 돌아가는 중간에 새 지시를 끼워 넣는 것도 가능하다.

![클로드 코드가 지시서를 쓰고 코덱스 일꾼을 띄우고 기다리고 결과를 확인하는 순서도](/images/codex-cli/fig-flow.png)

*클로드 코드가 코덱스 일꾼에게 일을 시키는 순서. 지시서를 쓰고, 띄우고, 따로 기다리고, 결과를 직접 확인한다*

![코덱스 일꾼 터미널 첫 화면. gpt-6.1-sol · medium](/images/codex-cli/term-worker.png)

*이 글의 자료 조사를 맡은 코덱스 일꾼의 터미널. 모델(gpt-6.1-sol)과 추론 강도(medium)가 맨 위에 보인다*

실제 작업에서는 이렇게 굴러갔다. 지난 글에 들어갈 요금제 자료를 모을 때 클로드 코드는 Luna 일꾼 셋을 띄워 주제를 하나씩 나눴다. 그중 하나는 1분 33초 만에 조사를 마쳤다. 곧바로 Sol 일꾼이 투입돼 14분 46초 동안 공식 웹페이지와 조사 결과를 일일이 맞혀 봤고, 전체 91개 주장 묶음 가운데 32개를 바로잡았다. Luna가 예전 도움말 문서를 근거로 적어 온 대목이 꽤 많았기 때문이다.

![일꾼 완료 보고. 91개 묶음 중 32개 정정, 14분 46초, 이어서 시키기 명령](/images/codex-cli/term-done.png)

*대조를 맡은 Sol 일꾼이 끝났을 때 클로드 코드가 받은 보고. 마지막 줄이 같은 세션을 이어서 시키는 명령이다*

화면 캡처는 Terra 일꾼 몫이었다. 내 Claude 사용량 페이지와 결제 창을 띄워 스크린샷을 찍은 뒤 이름과 카드 번호 위에 검은 상자를 덧씌웠다. 혹시 모를 사고를 막으려고 결제 폼에는 아무 값도 넣지 말고 취소 버튼으로 닫으라고 지시서에 못 박아 뒀다.

이 글을 포함해 오늘 블로그 글 3편을 쓰는 동안 클로드 코드가 호출한 코덱스 일꾼은 모두 12개다. 그중 하나는 실패로 끝났다. Paseo 화면을 찍으러 갔던 Terra 일꾼이 터미널 목록을 찾지 못하자, 괜히 다른 데를 건드리는 대신 그대로 멈춰 섰다. 지시서에 하지 말아야 할 일을 분명히 적어 두면 모를 때 알아서 멈춘다.

![2026년 11월 10일 클로드 코드가 띄운 코덱스 일꾼 12개의 모델과 걸린 시간 표](/images/codex-cli/fig-runs.png)

*오늘 클로드 코드가 띄운 코덱스 일꾼 12개. 조사는 Luna와 Sol, 화면 캡처는 Terra가 맡았다*

## 모델은 어떻게 고를까?

코덱스 안에서도 일감에 따라 모델을 나눠 쓴다. 내가 잡은 기준은 이렇다.

- **구현은 Sol.** 코드를 짜거나 고치는 작업, 문서를 꼼꼼하게 대조하는 작업에 쓰며 평소 가장 자주 부른다.
- **조사는 Luna.** 비용이 제일 저렴해서 여럿을 동시에 띄워 주제를 하나씩 던져 줄 때 좋다. 다만 결과물을 그대로 쓰지 않고 Sol이나 클로드에게 검수를 맡긴다.
- **화면 조작은 Terra.** 브라우저나 데스크톱 앱 화면을 읽고 버튼을 누르거나 캡처할 때 쓴다.
- **Astra는 거의 안 쓴다.** 화면 인식이 유독 까다롭거나 정말 중요한 작업에만 아껴 쓴다. 사용량을 워낙 빠르게 깎아 먹어서 평소에는 Sol로도 충분하다.

![Sol은 구현, Luna는 조사, Terra는 화면 조작, Astra는 가끔 쓰는 모델 기준 카드](/images/codex-cli/fig-models.png)

*코덱스 모델을 고르는 내 기준. 대부분은 Sol, 조사는 Luna, 화면은 Terra로 한다*

OpenAI 공식 안내도 결이 크게 다르지 않다. 가장 복잡한 문제에는 Astra를, 그에 준하는 성능을 아껴 쓰고 싶을 때는 Sol을 권한다. 글쓰기나 화면 인식 및 컴퓨터 조작에는 Terra, 범위가 명확한 반복 작업에는 Luna를 쓰라고 설명한다.

## 꼭 해 두는 설정은 뭘까?

내가 챙기는 설정은 딱 두 가지다.

**첫째, AGENTS.md를 쓴다.** 코덱스는 프로젝트 폴더 안의 AGENTS.md를 읽어들여 작업 지침으로 삼는다. 전역 설정부터 프로젝트 루트, 현재 작업 폴더 순으로 파일을 찾아 합쳐 읽는 구조다.

반면 클로드 코드는 원래 CLAUDE.md를 찾는다. 최신 버전(v2.1.277 이상)부터는 AGENTS.md도 읽을 줄 알지만, 같은 폴더에 CLAUDE.md가 함께 있으면 CLAUDE.md만 읽고 끝낸다. 그래서 나는 모든 규칙을 AGENTS.md 한 파일에만 몰아 적고, CLAUDE.md에는 아래 한 줄만 남겨 둔다.

```
@AGENTS.md
```

이렇게 묶어 두면 두 도구가 언제나 똑같은 문서를 바라본다. 한쪽 지침만 고쳐 놓고 다른 쪽을 잊어버릴 일이 없다.

![CLAUDE.md에는 @AGENTS.md 한 줄, AGENTS.md에 공통 지침을 쓴 실제 파일](/images/codex-cli/fig-agents.png)

*내 지식 저장소의 실제 CLAUDE.md와 AGENTS.md. 지침은 AGENTS.md에만 쓴다*

**둘째, 추론 강도(effort)를 처음부터 높이지 않는다.** 평소에는 대개 medium에 맞춰 둔다. 단계를 높이면 응답이 느려지고 사용량 한도도 금방 닳는데, 그렇다고 결과물이 매번 눈에 띄게 좋아지지도 않았다.

OpenAI 공식 문서에서도 각 클라이언트의 기본값으로 시작한 뒤 작업 난이도에 맞춰 조절하라고 권한다. 모델마다 권장하는 출발점도 조금씩 달라서 Sol은 기본값, Luna는 high, Astra는 낮은 단계부터 시작하라고 안내한다. 나는 주력이 Sol이라 medium으로 문을 열고, 풀리지 않는 문제를 만났을 때만 단계를 올린다.

이 설정은 `~/.codex/config.toml` 파일에 적어 두면 된다.

```
model = "gpt-6.1-sol"
model_reasoning_effort = "medium"
```

## 누구에게 코덱스가 필요할까?

코드를 만지지 않고 일반 업무에만 AI를 쓴다면 굳이 코덱스까지 넘어올 이유는 없다. 클로드 하나로도 충분하다.

하지만 글이나 작업 중에 이미지를 자주 뽑아야 한다면 코덱스 쪽이 훨씬 편하다. 코덱스 CLI 안에서도 바로 이미지를 생성할 수 있다.

만약 코딩을 하는 사람이라면 코덱스를 클로드 코드의 대체재가 아니라 손발이 되어 줄 일꾼으로 바라보길 권한다. 방향을 잡고 결과를 검수하는 일은 클로드에게 맡기고, 잔손이 많이 가는 조사나 반복 작업은 코덱스에게 떼어 주는 식이다.

지금 클로드 코드를 쓰고 있다면 당장 프로젝트 폴더에 AGENTS.md 파일을 만들고 CLAUDE.md에 `@AGENTS.md` 한 줄만 적어 넣어 보자. 코덱스 일꾼을 데려다 쓸 준비는 그것만으로 이미 절반은 끝난다.
