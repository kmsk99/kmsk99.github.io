나는 코덱스 CLI를 터미널에서 직접 여는 일이 거의 없다. 그래도 코덱스는 매일 일한다. 클로드 코드가 대신 시키기 때문이다.

이 글에 들어간 설치 방법과 설정도 코덱스 일꾼이 공식 문서에서 찾아 왔다. 시킨 건 클로드 코드였고, 나는 결과만 받았다.

처음부터 이렇게 쓴 건 아니다.

(2026년 11월 기준. 내 환경은 codex-cli 0.166.0이다.)

## 코덱스 CLI가 뭘까?

코덱스 CLI는 OpenAI가 만든 터미널용 코딩 에이전트다. 클로드 코드와 비슷하게 터미널에서 대화하며 코드를 읽고 고친다.

설치는 둘 중 하나로 한다.

```
npm install -g @openai/codex
brew install --cask codex
```

로그인은 ChatGPT 계정으로 하거나 API 키로 한다. ChatGPT 계정으로 하면 쓰는 만큼 요금제 한도에서 빠지고, API 키로 하면 쓴 만큼 돈을 낸다. macOS, 리눅스, 윈도우에서 돌아가고, 윈도우는 WSL2도 된다.

![codex --version과 codex --help 출력. codex-cli 0.166.0, exec·login·resume 명령](/images/codex-cli/term-install.png)

*설치하면 codex 명령이 생긴다. exec는 대화 없이 일을 시킬 때, resume은 끊긴 세션을 이어 갈 때 쓴다*

## 처음엔 어떻게 쓰게 됐을까?

나는 클로드보다 ChatGPT를 먼저 썼다. 채팅으로 쓰다가 코덱스가 나와서 코덱스까지 쓰게 됐다.

가장 많이 쓴 건 카카오톡 프로모션으로 ChatGPT 프로를 플러스 요금으로 5개월 쓸 수 있었을 때다. 그때 느낌은 이랬다. 클로드 코드보다는 조금 덜하지만, 나쁘지 않다.

지금은 ChatGPT Pro의 월 200달러 등급을 쓴다. 클로드와 같이 쓰는 이유는 [지난 글](https://kmsk99.github.io/post/claude-code-plans/)에 적었다. 이미지를 만들 수 있고, 사용량이 넉넉하다고 느끼기 때문이다.

## 왜 직접 안 쓰고 클로드 코드에게 시킬까?

코덱스를 혼자 쓸 때 가장 짜증 났던 건 세션이 조용히 꺼지는 일이었다.

일을 시켜 놓고 한참 뒤에 보면 아무 말 없이 멈춰 있었다. 중간중간 용량 부족(capacity) 오류가 나는데, 그러면 그 자리에서 끝나 버렸다. 내가 다시 이어서 시켜야 했다.

클로드 코드에게 코덱스를 부리게 하자 이게 해결됐다. 코덱스 세션이 중간에 꺼져도, 클로드 코드가 그걸 알아채고 같은 세션을 다시 이어서 시킨다. 내가 지켜보고 있을 필요가 없다.

그래서 지금 내가 터미널에서 코덱스를 직접 여는 건 컴퓨터 화면이나 인터넷 창을 조작하게 할 때 정도다. 나머지는 거의 다 클로드 코드가 시킨다.

당신도 코덱스에게 긴 일을 맡겼다가 멈춘 걸 나중에 발견한 적이 있다면, 지켜보는 역할을 다른 에이전트에게 넘겨 볼 만하다.

## 클로드 코드는 코덱스에게 어떻게 일을 시킬까?

나는 이걸 위해 `agent-delegate`라는 스킬을 만들어 쓴다. 클로드 코드가 이 스킬을 읽고, 정해진 순서대로 코덱스 일꾼을 띄운다.

순서는 이렇다.

- **일을 적는다.** 클로드 코드가 목표, 작업 폴더, 해도 되는 일과 하면 안 되는 일(커밋 금지, 결제 금지 같은 것), 결과를 어디에 남길지를 지시서 한 장에 적는다.
- **일꾼을 띄운다.** 모델과 추론 강도(effort)를 정해서 코덱스를 실행한다. 일꾼마다 터미널 창이 하나씩 열려서 내가 진행 상황을 볼 수 있다.
- **기다린다.** 일꾼마다 따로 기다린다. 먼저 끝난 일꾼부터 결과를 확인하고, 그동안 다른 일꾼은 계속 일한다.
- **확인한다.** 일꾼이 "다 했다"고 해도 그대로 믿지 않는다. 클로드 코드가 결과 파일을 직접 열어 보고, 시킨 범위를 지켰는지 확인한다.
- **이어서 시킨다.** 더 시킬 게 있거나 세션이 꺼졌으면, 같은 세션 번호로 이어서 시킨다. 일하는 도중에 지시를 하나 더 끼워 넣을 수도 있다.

![클로드 코드가 지시서를 쓰고 코덱스 일꾼을 띄우고 기다리고 결과를 확인하는 순서도](/images/codex-cli/fig-flow.png)

*클로드 코드가 코덱스 일꾼에게 일을 시키는 순서. 지시서를 쓰고, 띄우고, 따로 기다리고, 결과를 직접 확인한다*

![코덱스 일꾼 터미널 첫 화면. gpt-6.1-sol · medium](/images/codex-cli/term-worker.png)

*이 글의 자료 조사를 맡은 코덱스 일꾼의 터미널. 모델(gpt-6.1-sol)과 추론 강도(medium)가 맨 위에 보인다*

실제로는 이렇게 썼다. 지난 글의 요금 자료를 모을 때, 클로드 코드가 Luna 일꾼 3개에게 주제를 하나씩 나눠 맡겼다. 그중 하나는 1분 33초 만에 끝났다. 그다음 Sol 일꾼이 14분 46초 동안 그 결과를 공식 페이지와 하나씩 대조했다. 91개 주장 묶음 가운데 32개를 고쳤다. Luna가 옛 도움말을 보고 쓴 내용이 많았기 때문이다.

![일꾼 완료 보고. 91개 묶음 중 32개 정정, 14분 46초, 이어서 시키기 명령](/images/codex-cli/term-done.png)

*대조를 맡은 Sol 일꾼이 끝났을 때 클로드 코드가 받은 보고. 마지막 줄이 같은 세션을 이어서 시키는 명령이다*

화면 캡처는 Terra 일꾼이 했다. 내 Claude 사용량 화면과 결제 화면을 열어 찍고, 이름과 카드 정보를 검은 상자로 가렸다. 결제 폼은 아무것도 입력하지 않고 취소로 닫으라고 지시서에 적어 뒀다.

이 글을 포함해 오늘 블로그 글 3편을 만드는 동안, 클로드 코드가 띄운 코덱스 일꾼은 12개였다. 하나는 실패했다. Paseo 화면을 찍으려던 Terra 일꾼이 터미널 목록을 찾지 못해, 아무것도 건드리지 않고 멈췄다. 하면 안 되는 일을 지시서에 적어 두면 이렇게 멈출 줄도 안다.

![2026년 11월 10일 클로드 코드가 띄운 코덱스 일꾼 12개의 모델과 걸린 시간 표](/images/codex-cli/fig-runs.png)

*오늘 클로드 코드가 띄운 코덱스 일꾼 12개. 조사는 Luna와 Sol, 화면 캡처는 Terra가 맡았다*

## 모델은 어떻게 고를까?

코덱스는 모델을 골라 쓴다. 내 기준은 이렇다.

- **구현은 Sol.** 코드를 짜고 고치는 일, 꼼꼼히 대조하는 일. 가장 많이 쓴다.
- **조사는 Luna.** 가장 싸다. 여러 개를 동시에 돌려서 주제를 하나씩 맡긴다. 대신 결과를 그대로 믿지 않고 Sol이나 클로드가 한 번 더 본다.
- **화면 조작은 Terra.** 브라우저나 앱 화면을 보고 누르는 일, 캡처하는 일.
- **Astra는 거의 안 쓴다.** 화면이 정말 중요하거나 아주 중요한 일에만 쓴다. 사용량을 너무 많이 써서, 웬만하면 Sol로 한다.

![Sol은 구현, Luna는 조사, Terra는 화면 조작, Astra는 가끔 쓰는 모델 기준 카드](/images/codex-cli/fig-models.png)

*코덱스 모델을 고르는 내 기준. 대부분은 Sol, 조사는 Luna, 화면은 Terra로 한다*

OpenAI의 설명도 비슷하다. Astra는 가장 어려운 일용, Sol은 Astra에 가까운 성능을 더 적은 비용으로, Terra는 글쓰기·화면 보기·컴퓨터 조작용, Luna는 범위가 정해진 반복 작업용이라고 안내한다.

## 꼭 해 두는 설정은 뭘까?

두 가지다.

**첫째, AGENTS.md를 쓴다.** 코덱스는 프로젝트 폴더의 AGENTS.md를 읽고 그 지침대로 일한다. 전역 설정, 프로젝트 루트, 지금 폴더 순서로 합쳐서 읽는다.

클로드 코드는 원래 CLAUDE.md를 읽는다. 최신 버전(v2.1.277 이상)은 AGENTS.md도 직접 읽는다. 다만 같은 곳에 CLAUDE.md가 있으면 CLAUDE.md만 읽는다. 그래서 나는 지침을 AGENTS.md 한 곳에만 쓰고, CLAUDE.md에는 이 한 줄만 둔다.

```
@AGENTS.md
```

이러면 클로드 코드와 코덱스가 같은 지침을 본다. 한쪽만 고치고 다른 쪽을 깜빡하는 일이 없다.

![CLAUDE.md에는 @AGENTS.md 한 줄, AGENTS.md에 공통 지침을 쓴 실제 파일](/images/codex-cli/fig-agents.png)

*내 지식 저장소의 실제 CLAUDE.md와 AGENTS.md. 지침은 AGENTS.md에만 쓴다*

**둘째, 추론 강도(effort)를 처음부터 높이지 않는다.** 나는 웬만하면 medium으로 쓴다. 높이면 느려지고 한도도 빨리 준다. 그런데 결과가 항상 좋아지지는 않았다.

참고로 OpenAI는 클라이언트 기본값에서 시작해 일에 맞게 조절하라고 안내한다. 모델마다 시작점도 다르게 안내한다. Sol은 기본값, Luna는 high, Astra는 낮은 단계부터다. 나는 대부분 Sol을 쓰니 medium에서 시작하고, 막힐 때만 올린다.

설정은 `~/.codex/config.toml`에 적는다.

```
model = "gpt-6.1-sol"
model_reasoning_effort = "medium"
```

## 누구에게 코덱스가 필요할까?

코딩을 하지 않고 AI를 쓴다면 굳이 코덱스로 올 필요는 없다. 클로드만으로 충분하다.

다만 이미지를 만들어야 한다면 코덱스가 낫다. 코덱스 CLI에서도 이미지를 만들 수 있다.

그리고 코딩을 한다면, 코덱스를 클로드 코드의 경쟁자보다 일꾼으로 보는 걸 권한다. 클로드에게는 판단과 확인을 맡기고, 코덱스에게는 손이 많이 가는 일을 나눠 준다.

당신이 클로드 코드를 쓰고 있다면, 오늘 프로젝트에 AGENTS.md를 하나 만들고 CLAUDE.md에 `@AGENTS.md` 한 줄을 넣어 보자. 코덱스를 붙일 준비는 그걸로 반은 끝난다.
